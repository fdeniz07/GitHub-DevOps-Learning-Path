# GitHub Releases Quiz

## Multiple Choice

### Question 1

What does a Git tag primarily identify?

- A. A discussion category
- B. A specific commit in Git history
- C. A project board column
- D. A GitHub user

#### Answer and Explanation: Question 1

**B.** A tag gives a stable name to one exact commit.

### Question 2

What is the main purpose of GitHub Release notes?

- A. To replace the repository history
- B. To explain the changes and upgrade implications of a version
- C. To rename the default branch
- D. To create a local clone

#### Answer and Explanation: Question 2

**B.** Release notes communicate what changed and what users should know before upgrading.

## Short Answer

### Question 3

What is the difference between a prerelease and a stable release?

#### Answer and Explanation: Question 3

A prerelease is shared for testing before final approval, while a stable release is presented as ready for normal use.

## Practical Scenario

A project has removed a configuration format that existed in the previous version. Which Semantic Versioning component should normally change, and what should the release notes include?

### Expected Answer: Practical Scenario

The major version should normally increase because the change may be incompatible. The release notes should describe the breaking change and provide migration instructions.
