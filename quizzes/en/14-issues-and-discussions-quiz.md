# Issues and Discussions Quiz

## Multiple Choice

### Question 1

When is a GitHub Issue usually the best choice?

- A. When a team wants to explore an idea without a defined task
- B. When a bug or requested change needs to be tracked toward an outcome
- C. When a user wants to rename a local branch
- D. When a repository needs a new remote

#### Answer and Explanation: Question 1

**B.** Issues are designed for trackable bugs, tasks, enhancements, and other requests with a concrete outcome.

### Question 2

When is a GitHub Discussion usually the better choice?

- A. When a reproducible bug must be fixed
- B. When a pull request is ready for merge
- C. When people need to ask questions or explore an idea
- D. When a release tag must be created

#### Answer and Explanation: Question 2

**C.** Discussions support open conversation, questions, ideas, and shared knowledge.

## Short Answer

### Question 3

Name two pieces of information that make a bug issue easier to act on.

#### Answer and Explanation: Question 3

Useful information includes reproduction steps, expected behavior, actual behavior, logs, screenshots, and a clear description of the affected environment.

## Practical Scenario

A contributor opens a discussion about a possible documentation improvement. The community agrees that one specific page must be corrected before the next release. What should happen next?

### Expected Answer: Practical Scenario

Create or update a focused issue with the agreed scope, acceptance criteria, owner, and milestone. The discussion can remain linked as the context for the decision.
