# AI Guidelines

## Purpose

This document defines how AI assistants should collaborate when contributing to the GitHub & DevOps Learning Path repository.

Its goal is to ensure that AI-generated contributions remain consistent, maintainable, and aligned with the project's educational vision and architecture.

---

# Core Principles

AI should support the development process, not replace architectural or educational decisions.

All contributions must prioritize:

- Consistency
- Accuracy
- Simplicity
- Maintainability
- Educational value

---

# AI Workflow

Every proposed change should follow this workflow:

1. Proposal
2. Review
3. Approval
4. Implementation
5. Verification

No direct implementation should occur without review and approval.

---

# AI Responsibilities

AI assistants may:

- Improve documentation
- Generate educational content
- Create notebooks
- Write exercises and labs
- Generate quizzes
- Improve formatting
- Detect inconsistencies
- Suggest improvements
- Review Markdown structure

AI should avoid making architectural decisions independently.

---

# Prompt Writing Rules

Prompts should:

- Clearly define the objective.
- Specify the target file.
- Preserve existing structure unless instructed otherwise.
- Request complete, production-ready output.
- Avoid ambiguous instructions.

Whenever possible, prompts should include repository context.

---

# Modification Rules

Unless explicitly requested, AI should:

- Preserve document structure.
- Preserve educational intent.
- Preserve existing file names.
- Preserve repository organization.
- Avoid unnecessary rewrites.

Large structural changes require explicit approval.

---

# Repository Protection Rules

AI must not:

- Rename repository directories.
- Move educational content.
- Delete documentation.
- Remove navigation links.
- Change repository architecture.
- Modify project identity.

Repository-wide changes require human approval.

---

# Architecture Protection

The repository architecture defined in `ARCHITECTURE.md` is considered the source of truth.

AI should not:

- Introduce new top-level directories.
- Change artifact relationships.
- Redesign repository organization.
- Modify governance structure.

Architectural proposals should be submitted as recommendations rather than direct changes.

---

# Allowed Operations

AI may:

- Correct grammar and spelling.
- Improve readability.
- Expand educational explanations.
- Create examples.
- Generate diagrams in Markdown.
- Improve consistency.
- Suggest best practices.
- Create missing educational artifacts.

---

# Forbidden Operations

AI must not:

- Invent technical facts.
- Remove educational content without approval.
- Duplicate information unnecessarily.
- Break internal navigation.
- Introduce incompatible standards.
- Generate placeholder content presented as finished work.

---

# Review Rules

Every AI-generated contribution should be reviewed for:

- Technical accuracy
- Educational quality
- Repository consistency
- Markdown formatting
- Link validation
- Naming conventions

Only reviewed content should be considered complete.

---

# Commit Rules

AI should never generate commits automatically.

Before committing, verify that:

- The change has been approved.
- Documentation is consistent.
- Markdown has been validated.
- Internal links are correct.
- Related files remain synchronized.

Recommended commit messages should follow the repository's commit convention.

---

# Best Practices

- Prefer clarity over complexity.
- Keep explanations concise.
- Use real-world examples whenever possible.
- Follow existing repository conventions.
- Reuse templates instead of creating new structures.
- Keep educational content focused on learning objectives.
- Make incremental improvements rather than large rewrites.

The role of AI is to assist contributors, accelerate content creation, and improve quality while preserving the long-term consistency of the repository.
