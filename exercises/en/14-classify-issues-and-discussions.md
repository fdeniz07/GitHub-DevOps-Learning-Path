# Classify Issues and Discussions

## Objective

Choose the correct GitHub communication tool and create useful context for a trackable work item.

## Scenario

You are helping maintain a public repository. Community members report bugs, ask questions, and suggest improvements. Your task is to decide which requests should become issues and which should remain discussions.

## Tasks

1. Classify four example requests as an issue or discussion.
2. Search the repository for possible duplicates before creating a new item.
3. Rewrite one vague request as a clear issue.
4. Add suitable labels, an assignee, and a milestone.
5. Explain when a discussion should become an issue.

## Expected Outcome

You can distinguish exploratory conversation from trackable work and write an issue that another contributor can act on.

## Self-Check

- [ ] I know when to use an issue instead of a discussion.
- [ ] I can write clear reproduction steps.
- [ ] I understand how labels and milestones support triage.
