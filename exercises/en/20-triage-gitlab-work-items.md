## Triage GitLab Work Items

## Objective

Turn vague incoming requests into prioritized, actionable GitLab work items.

## Scenario

Your team receives these requests: `Login is broken`, `Add dark mode`, and `Typo in setup guide`. The release is tomorrow, login failures affect many users, and the documentation typo does not block setup.

## Tasks

### Task 1 - Improve the records

Rewrite each title so it communicates an outcome. Add a short description and at least two acceptance criteria for the login item.

**Expected Result:**

Another teammate can understand the problem, expected behavior, and evidence needed for completion.

### Task 2 - Classify and prioritize

Choose consistent labels for type, area, and priority. Order the items and explain the two most important factors behind your decision.

**Expected Result:**

The login item is treated as urgent based on impact and deadline; the other work remains visible without receiving false urgency.

### Task 3 - Plan ownership

Assign an owner to each ready item. Decide which items belong in the next milestone and how a board or planning view could show their status.

### Expected Result

Each item has a clear next action, accountable person, and planning location where supported.

## Self-Assessment

- [ ] I can distinguish an outcome from a vague request.
- [ ] I can write observable acceptance criteria.
- [ ] I can prioritize using impact and urgency.
- [ ] I can use labels and milestones consistently.

## Common Mistakes

| Mistake                                     | Solution                                                   |
| ------------------------------------------- | ---------------------------------------------------------- |
| Assigning a priority without a reason       | Record the impact and time pressure that justify it.       |
| Treating a label as an acceptance criterion | Use labels for classification and criteria for completion. |
