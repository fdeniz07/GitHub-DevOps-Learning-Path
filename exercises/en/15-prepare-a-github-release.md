# Prepare a GitHub Release

## Objective

Plan a clear versioned release and identify the checks required before publishing it.

## Scenario

A project has completed a group of features and fixes. The maintainers want to publish a stable version that users can understand and download confidently.

## Tasks

1. Choose a version number using Semantic Versioning.
2. List the commits, issues, or pull requests that belong in the release.
3. Write release notes with highlights, fixes, and upgrade information.
4. Decide whether the release should be draft, prerelease, or stable.
5. Create a release readiness checklist with at least six items.

## Expected Outcome

You can explain how a tag, release notes, and release assets work together to communicate a project version.

## Self-Check

- [ ] I can distinguish a tag from a GitHub Release.
- [ ] I can choose a major, minor, or patch version.
- [ ] I know why release notes should describe user impact.
