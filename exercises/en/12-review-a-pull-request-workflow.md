# Review a Pull Request Workflow

## Objective

Inspect a pull request as a reviewer and identify the communication, review, and merge steps that make GitHub collaboration effective.

## Scenario

A teammate has created a feature branch and opened a pull request. You need to review the changes, understand the intent, and decide whether the branch is ready to merge.

## Tasks

1. Open a PR in GitHub or a sample repository.
2. Inspect the diff and identify the exact files changed.
3. Read the PR description and verify whether the intent is clear.
4. Add one helpful review comment.
5. Explain whether the PR is ready to merge and why.

## Expected Outcome

You can evaluate a pull request by reviewing the changes, checking intent, and understanding what conditions should be met before merging.

## Self-Check

- [ ] I can describe what a pull request is.
- [ ] I know how a reviewer evaluates a PR beyond syntax.
- [ ] I can explain why review comments are part of the collaboration process.
