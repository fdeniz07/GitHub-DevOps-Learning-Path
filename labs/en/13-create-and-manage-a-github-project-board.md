# Create and Manage a GitHub Project Board

## Objective

Practice creating and maintaining a simple GitHub Project board that tracks tasks through a realistic development workflow.

## Requirements

- A GitHub repository or organization project
- Access to create projects
- At least one issue or pull request to add to the board

## Tasks

### Task 1 - Create a New Project

Open GitHub and create a new project. Choose a board view and give it a meaningful name.

### Task 2 - Define Workflow Columns

Create columns such as:

```text
Backlog
In Progress
Review
Done
```

### Task 3 - Add Work Items

Add at least two issues or pull requests to the project and place them in the correct columns.

### Task 4 - Move Items as Progress Changes

Move one item from **In Progress** to **Review** and then to **Done** after completion.

### Task 5 - Check Visibility

Review the board and explain how it helps the team see the current delivery state.

## Expected Outcome

You can create a working project board and explain how it supports coordination, tracking, and delivery visibility.

## Troubleshooting

| Problem               | Resolution                                               |
| --------------------- | -------------------------------------------------------- |
| Board feels too empty | Add issues and pull requests for realistic tasks.        |
| Columns are unclear   | Align each column with a real stage in the workflow.     |
| Work is not visible   | Keep the board updated and move cards as status changes. |
