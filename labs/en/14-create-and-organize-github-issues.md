# Create and Organize GitHub Issues

## Objective

Practice creating a clear issue, adding useful metadata, and connecting the work to a project workflow.

## Requirements

- A GitHub repository where you can create issues
- Permission to add labels, assignees, or project items
- A small example bug or documentation improvement

## Tasks

### Task 1 - Search Before Creating

Search the repository's issues and discussions for an existing item that describes the same problem. Avoid creating a duplicate.

### Task 2 - Create a Focused Issue

Create an issue with:

- a specific title;
- context and expected behavior;
- actual behavior;
- reproduction steps or acceptance criteria.

### Task 3 - Add Metadata

Add a suitable label, assign an owner, and attach the issue to a milestone if one exists.

### Task 4 - Add the Issue to a Project

Place the issue in the appropriate project stage, such as **Backlog** or **Todo**.

### Task 5 - Link the Delivery Work

Create a feature branch and pull request if appropriate. Reference the issue in the pull request description so the work remains traceable.

## Expected Outcome

You can create a useful GitHub issue and organize it so that its status, ownership, and delivery relationship are visible.

## Troubleshooting

| Problem                     | Resolution                                                       |
| --------------------------- | ---------------------------------------------------------------- |
| The issue is too vague      | Add context, reproduction steps, and expected behavior.          |
| A duplicate may exist       | Search titles, labels, and discussions before creating it.       |
| No project is visible       | Ask a repository maintainer which project should track the work. |
| The task has no clear owner | Assign the responsible contributor or team role.                 |
